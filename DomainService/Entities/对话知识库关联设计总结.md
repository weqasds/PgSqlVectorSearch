# 对话知识库关联设计总结

## 1. 需求分析

### 1.1 原始需求
- 用户需要知道历史对话会话中用到了哪些知识库
- 防止向数据库中重复上传同一文件
- 不破坏现有实体结构，保持向后兼容性

### 1.2 解决方案设计
1. **对话-知识库关联**：采用一对多关系，对话会话关联一个主要知识库，同时记录引用的其他知识库
2. **文件去重**：在KnowledgeDocument中添加文件哈希字段
3. **简化设计**：避免多对多关系的复杂性，符合主流RAG系统设计模式

### 1.3 设计变更说明
原设计采用多对多关系（通过ChatSessionKnowledgeBase中间表），但考虑到以下因素改为一对多关系：

**变更原因：**
1. **主流RAG系统设计**：大多数RAG系统采用一对多关系，对话通常关联一个主要知识库
2. **简化复杂性**：多对多关系增加开发复杂度和维护成本
3. **实际使用场景**：对话通常有一个主要知识库，引用其他知识库可通过检索策略实现

**新设计方案：**
1. **一对多核心关系**：ChatSession → KnowledgeBase（一个对话有一个主要知识库）
2. **多知识库引用**：通过`ReferencedKnowledgeBaseIds`字段记录对话中实际引用的所有知识库
3. **向后兼容**：所有修改保持现有功能不变

## 2. 实体设计修改

### 2.1 新增实体：ChatSessionKnowledgeBase

**位置：** `DomainService/Entities/Chat/ChatSessionKnowledgeBase.cs`

**字段定义：**
- `Id` (Guid)：主键
- `ChatSessionId` (Guid)：对话会话ID
- `KnowledgeBaseId` (Guid)：知识库ID
- `ChatSession` (ChatSession)：对话会话导航属性
- `KnowledgeBase` (KnowledgeBase)：知识库导航属性
- `FirstUsedAt` (DateTime)：首次使用时间
- `LastUsedAt` (DateTime)：最后使用时间
- `UsageCount` (int)：在该对话中使用次数

**设计要点：**
- 复合唯一索引：确保每个对话对每个知识库只有一条记录
- 时间跟踪：记录首次和最后使用时间
- 使用计数：统计知识库在对话中的使用频率

### 2.2 修改实体：ChatSession

**位置：** `DomainService/Entities/Chat/ChatSession.cs`

**新增导航属性：**
- `KnowledgeBases` (ICollection<ChatSessionKnowledgeBase>?)：该对话使用的知识库关联关系

**作用：**
- 通过此属性查询对话使用的所有知识库
- 支持双向导航，便于数据查询

### 2.3 修改实体：KnowledgeBase

**位置：** `DomainService/Entities/KnowledgeManagement/KnowledgeBase.cs`

**新增导航属性：**
- `ChatSessions` (ICollection<ChatSessionKnowledgeBase>?)：使用该知识库的对话会话关联关系

**作用：**
- 通过此属性查询使用该知识库的所有对话
- 支持从知识库角度分析使用情况

### 2.4 修改实体：KnowledgeDocument

**位置：** `DomainService/Entities/KnowledgeManagement/KnowledgeDocument.cs`

**新增字段：**
- `FileHash` (string?)：文件哈希值，用于防止重复上传相同文件

**设计要点：**
- 可空字段：现有文档可能没有哈希值
- 长度限制：64字符，支持常用哈希算法（SHA256等）
- 索引：添加FileHash索引，加快重复文件查找

## 4. 数据模型关系图（简化设计）

### 4.1 核心一对多关系
```
User (1) ──── (n) ChatSession (n) ──── (1) KnowledgeBase
                      │
                      ├── KnowledgeBaseId（外键，可为空）
                      ├── KnowledgeBase（导航属性）
                      └── ReferencedKnowledgeBaseIds（JSON数组，记录引用的其他知识库）
```

### 4.2 文件去重关系
```
KnowledgeBase (1) ──── (n) KnowledgeDocument
                              │
                              └── FileHash（新增，用于重复文件检测）
```

### 4.3 多知识库引用机制
```
对话会话 (ChatSession)
├── 主要知识库：KnowledgeBaseId（直接关联）
└── 引用知识库：ReferencedKnowledgeBaseIds（JSON数组）
    ├── 知识库ID 1
    ├── 知识库ID 2
    └── 知识库ID 3
```

**设计优势：**
1. **简化关系**：一对多比多对多更简单、更高效
2. **灵活引用**：通过JSON字段支持多知识库引用，无需复杂的关系表
3. **查询优化**：直接外键关联，避免中间表连接
4. **扩展性强**：JSON格式便于存储额外信息（如引用次数、引用时间等）

## 5. 业务逻辑实现建议

### 5.1 对话知识库记录逻辑

**使用场景：**
1. 用户发起对话时选择知识库
2. AI回复时检索知识库内容
3. 对话过程中切换知识库

**记录时机：**
- 对话开始时记录首次使用
- 每次知识库检索时更新最后使用时间和使用计数

**示例代码：**
```csharp
public async Task RecordKnowledgeBaseUsage(Guid chatSessionId, Guid knowledgeBaseId)
{
    var record = await context.ChatSessionKnowledgeBases
        .FirstOrDefaultAsync(x => x.ChatSessionId == chatSessionId &&
                                 x.KnowledgeBaseId == knowledgeBaseId);

    if (record == null)
    {
        record = new ChatSessionKnowledgeBase
        {
            ChatSessionId = chatSessionId,
            KnowledgeBaseId = knowledgeBaseId,
            FirstUsedAt = DateTime.UtcNow,
            LastUsedAt = DateTime.UtcNow,
            UsageCount = 1
        };
        context.ChatSessionKnowledgeBases.Add(record);
    }
    else
    {
        record.LastUsedAt = DateTime.UtcNow;
        record.UsageCount++;
        context.ChatSessionKnowledgeBases.Update(record);
    }

    await context.SaveChangesAsync();
}
```

### 5.2 文件去重逻辑

**实现方案：**
1. 上传文件时计算哈希值
2. 检查数据库中是否存在相同哈希值的文件
3. 如果存在，返回现有文档或提示用户

**示例代码：**
```csharp
public async Task<KnowledgeDocument?> FindDuplicateDocument(string fileHash, Guid knowledgeBaseId)
{
    return await context.KnowledgeDocuments
        .Where(x => x.FileHash == fileHash &&
                   x.KnowledgeBaseId == knowledgeBaseId)
        .FirstOrDefaultAsync();
}
```

## 7. 迁移注意事项

### 7.1 向后兼容性
- 所有新增字段均为可空或具有默认值
- 现有数据不受影响
- 现有API接口保持兼容

### 7.2 数据初始化
- 现有对话会话没有知识库使用记录，需逐步完善
- 现有文档没有文件哈希值，可在后续处理中计算并更新

### 7.3 性能考虑
- 复合唯一索引确保数据一致性
- FileHash索引加速重复文件查找
- 时间字段索引支持时间范围查询
