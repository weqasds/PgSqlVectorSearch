## 方案一：经典三栏布局（左导航 + 中聊天 + 右知识库）

> **最直觉、最像“专业工具”的布局**

![Image](https://s3-alpha.figma.com/hub/file/5082138728/96db0715-69bb-4a89-9972-0c57ee5e2125-cover.png)

![Image](https://d1eipm3vz40hy0.cloudfront.net/images/AMER/buildingaknowledgebase3.png)

![Image](https://blog.scottlogic.com/uploads/ai-tool-landscape.png)

### 📐 布局结构

```text
┌─────────┬───────────────┬──────────────┐
│ 侧边栏  │   聊天主界面   │ 知识库/引用  │
│(导航)  │               │ 可视化       │
└─────────┴───────────────┴──────────────┘
```

### 👍 优点

- 所有信息**同时可见**
- 聊天 ↔ 知识来源 **强关联**
- 非常适合 RAG（可显示引用 chunk、命中片段）
- 对“专业用户 / 开发者 / 学术”非常友好

### ⚠️ 缺点

- **横向空间压力大**
- 小屏（13 寸以下）体验一般
- 移动端基本不可用

### 🎯 适合场景

- 桌面端为主
- 企业 / 教育 / 内部系统
- 强 RAG 可解释性（引用、来源、向量命中）

### 💡 实现建议（Vue）

- CSS Grid 或 Flex
- 右栏支持 **collapse / resize**
- 聊天消息与知识库高亮联动（hover 同步）

## 方案二：左侧导航 + 中心聊天 + 知识库抽屉（Drawer）

> **ChatGPT / Copilot 风格，最“用户友好”**

![Image](https://cdn.dribbble.com/userupload/17424464/file/original-a64d809199a05b3cafb883be90527a3e.png?format=webp&resize=400x300&vertical=center)

![Image](https://cdn.prod.website-files.com/634e928d7acf0e5b9297c41b/69775d57f3f304914f8ac35d_New%20KB%20UI%20hero.webp)

![Image](https://cdn.dribbble.com/userupload/7530275/file/original-3fca82b77ce0a9e21491a851881c0640.png?format=webp&resize=400x300&vertical=center)

### 📐 布局结构

```text
┌─────────┬──────────────────────────┐
│ 侧边栏  │        聊天界面           │
│         │  [知识库 Drawer →]        │
└─────────┴──────────────────────────┘
```

### 👍 优点

- 聊天体验最沉浸
- 主界面干净
- **响应式友好**
- 适合普通用户

### ⚠️ 缺点

- 知识库是“被动查看”
- 不适合长时间对照分析
- 信息来回切换有成本

### 🎯 适合场景

- 面向普通用户
- 问答 / 助手型产品
- 移动端 / 平板

### 💡 实现建议

- 使用 `Drawer / Sheet`
- Drawer 内容支持 Tab（引用 / 文档 / 图谱）
- 由模型返回 `source_id` 决定是否自动弹出

## 方案三：上下分区（聊天在下，知识库在上）

> **“IDE / 分析工具”风格**

![Image](https://miro.medium.com/v2/resize%3Afit%3A1200/1%2Arqp7HW0Jve14HUCE6PLhAw.jpeg)

![Image](https://i.sstatic.net/qvLyS.png)

![Image](https://cdn.dribbble.com/userupload/11372244/file/original-ecf518f4a43401020e256161de7b1947.png?format=webp&resize=400x300&vertical=center)

### 📐 布局结构

```text
┌──────────────────────────────┐
│      知识库 / 文档 / 图谱     │
├──────────────────────────────┤
│          聊天输入 & 输出      │
└──────────────────────────────┘
```

### 👍 优点

- 适合**长文档 / PDF / 图谱**
- 上看资料，下问问题
- 符合“研究 / 学习”心智

### ⚠️ 缺点

- 聊天区高度受限
- 不适合高频短对话
- 移动端不友好

### 🎯 适合场景

- 学术阅读
- 法律 / 医疗 / 教材
- 文档问答型 RAG

### 💡 实现建议

- 上区支持分页 / 搜索 / 高亮
- 下区输入框固定（sticky）
- 滚动同步（chunk → chat）

## 方案四：多视图切换（Chat / Knowledge / Graph 独立页面）

> **最“工程化 / 可扩展”的布局**

![Image](https://media2.dev.to/dynamic/image/width%3D1000%2Cheight%3D420%2Cfit%3Dcover%2Cgravity%3Dauto%2Cformat%3Dauto/https%3A%2F%2Fdev-to-uploads.s3.amazonaws.com%2Fuploads%2Farticles%2F9730bs9dsy600kuzzvax.png)

![Image](https://cdn.dribbble.com/userupload/38512854/file/original-edb33c2011f0b948900b36f6c31958aa.png?format=webp&resize=400x300&vertical=center)

![Image](https://cdn.dribbble.com/userupload/46859979/file/066aba2329a11d86b5ca4ed10319d290.png?format=webp&resize=400x300&vertical=center)

### 📐 布局结构

```text
侧边栏
 ├─ Chat
 ├─ Knowledge Base
 ├─ Graph / Analytics
```

### 👍 优点

- 每个界面可做到**极致复杂**
- 逻辑清晰，代码好维护
- 非常适合多模块系统

### ⚠️ 缺点

- Chat 与知识库割裂
- 上下文切换成本高
- 不够“即时解释型”

### 🎯 适合场景

- 知识管理平台
- 企业内部系统
- 多 Agent / 多任务平台

### 💡 实现建议

- Vue Router + Layout Shell
- Chat 页面只展示引用摘要
- 点击跳转到 Knowledge 页面定位 chunk

## 方案五（进阶）：混合模式（推荐真实项目）

```text
默认：方案二（Drawer）
专业模式：方案一（三栏）
```

### 👍 优点

- 普通用户 & 专业用户都照顾
- 产品可成长
- 不推翻架构

### 🎯 适合场景

- 你这个 **RAG + Agent** 项目非常适合

### 💡 技术实现

- Layout Mode 存在 Pinia
- 用户设置 / 屏幕宽度自动切换
- 同一组件，不同容器
