### 2.4 仓储接口重构与向量存储

#### 仓储接口重构
- **遵循DDD聚合根原则**：移除非聚合根仓储接口，包括`IEmbeddingRepository`、`IChatMessageRepository`、`IKnowledgeChunkRepository`
- **仓储接口精简**：仅保留对应聚合根的仓储接口，确保领域访问路径清晰
- **向量存储职责分离**：引入`IVectorStore`基础设施服务接口，将向量存储和相似性搜索职责从领域层分离

#### 向量存储实现
- **EmbeddingRepository重构**：原`EmbeddingRepository`现实现`IVectorStore`接口，提供pgvector支持的向量操作
- **向量搜索功能**：实现基于L2距离和余弦距离的相似性搜索，支持过滤条件（知识库ID、文档ID）
- **距离度量标准化**：引入`DistanceMetric`枚举，支持L2、余弦、内积等距离度量标准

#### 影响与收益
- **架构清晰度**：仓储接口与聚合根一一对应，符合DDD原则
- **性能优化**：向量搜索逻辑集中，便于SQL优化和索引创建
- **可维护性**：向量存储作为基础设施服务，便于替换和扩展

## 3. 设计模式与架构原则

### 3.1 依赖倒置原则
- 领域层定义接口，基础设施层提供实现
- 高层模块不依赖低层模块，两者都依赖抽象

### 3.2 单一职责原则
- `IEmbeddingService`专注嵌入生成
- `ILLMService`专注LLM调用
- `IPromptTemplateService`专注提示工程
- `ISemanticKernelService`封装Semantic Kernel核心功能

### 3.3 接口隔离原则
- 每个接口都有明确的职责边界
- 客户端不应依赖它不需要的接口

### 3.4 CQRS模式
- 查询服务(`IQueryService`)与命令服务分离
- Repository负责写操作，QueryService负责复杂查询

## 5. 配置要求

### 5.1 项目引用
```xml
<!-- SemanticKernelAI.csproj需要添加 -->
<ProjectReference Include="..\DomainService\DomainService.csproj" />
```

### 5.2 依赖注入配置示例
```csharp
// Program.cs
services.AddScoped<IEmbeddingService, OpenAIEmbeddingService>();
services.AddScoped<ILLMService, OpenAILLMService>();
services.AddScoped<ISemanticKernelService, SemanticKernelService>();
services.AddScoped<IPromptTemplateService, PromptTemplateService>();

// Kernel配置
services.AddSingleton<Kernel>(sp =>
{
    var builder = Kernel.CreateBuilder();
    builder.AddOpenAIChatCompletion(modelId: "gpt-4", apiKey: configuration["OpenAI:ApiKey"]);
    builder.AddOpenAITextEmbeddingGeneration(modelId: "text-embedding-3-small", apiKey: configuration["OpenAI:ApiKey"]);
    return builder.Build();
});
```

### 5.3 配置文件

```json
    "ChatModel": "gpt-4"
  }

```
