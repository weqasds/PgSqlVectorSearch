# 🧾 Python文档解析服务执行计划书（精简优化版 · 无DDD）

---

# 🎯 项目目标

构建一个：

* 无状态
* 高性能
* 专注解析
* 易于C#调用

的文档解析服务，仅负责：

* PDF解析
* 旧版Office转换
* OCR补充识别

不负责：

* 持久化
* 复杂业务逻辑
* 状态管理

---

# 🏗️ 架构约束（执行前提）

* 采用 **3层结构（API / 服务 / 引擎）**
* 不使用DDD
* 优先同步处理
* 异步仅作为补充能力
* 所有处理尽量“内存完成 + 无副作用”

---

# 📅 执行阶段规划（优化版）

---

## 第一阶段：基础框架与运行环境

### 🎯 目标

构建最小可运行服务

### 核心任务

1. 初始化项目结构（精简目录）
2. 搭建 FastAPI 应用
3. 配置基础中间件：
   * 请求日志
   * 异常处理
4. 实现基础端点：
   * `/health`
   * `/ready`
5. 实现文件上传接口（支持流）
6. 配置基础日志（结构化日志）
7. 集成 Prometheus 指标采集
8. 配置环境变量与基础配置管理

### 交付物

* 可运行服务（支持健康检查）
* 基础日志与监控能力
* API基础框架

---

## 第二阶段：PDF解析核心能力

### 🎯 目标

完成PDF解析主流程

### 核心任务

1. 集成 PyMuPDF（主解析）
2. 集成 pdfplumber（表格补充）
3. 实现基础文本提取（分页）
4. 实现表格检测与提取
5. 实现简单解析策略分流：
   * 普通文本
   * 表格型文档
6. 实现解析服务封装（统一入口）
7. 控制内存使用（避免大文件爆内存）
8. 编写基础解析测试用例

### 交付物

* PDF解析能力（文本+表格）
* 基础解析API
* 测试样例

---

## 第三阶段：OCR能力集成（按需触发）

### 🎯 目标

增强对扫描PDF的支持

### 核心任务

1. 安装并配置 Tesseract OCR
2. 集成 pytesseract
3. 实现 OCR 调用逻辑
4. 实现 OCR 触发策略：
   * 文本提取为空或极少时触发
5. 控制 OCR 调用成本（避免全量执行）
6. 优化 OCR 性能（分页面处理）

### 交付物

* OCR解析能力
* OCR自动触发机制

## 第四阶段：Office文档转换

7. 增加转换结果校验

# 🧠 总体优化总结

相比原方案，本执行计划做了关键优化：

* ❌ 移除 Celery 强依赖（改轻量异步）
* ✅ 增加解析策略分流（避免单引擎问题）
* ✅ OCR按需触发（性能优化）
* ✅ LibreOffice隔离执行（稳定性提升）
* ✅ 明确同步优先（符合C#调用场景）
* ✅ 增加并发控制与限流（生产必备）
