# 语义内核集成实现计划

## 1. 项目概述

### 1.1 目标
将Microsoft Semantic Kernel集成到RAG系统中，实现完整的检索增强生成功能。包括文本嵌入生成、向量检索、LLM调用和提示工程等核心RAG功能。

### 1.2 当前状态
- SemanticKernelAI项目已创建，但为空项目
- 领域服务接口已定义（IVectorRetrievalService、IRagGenerationService等）
- RagGenerationService已部分实现，但缺少实际的AI服务集成
- PostgreSQL pgvector已配置，支持向量存储和相似度搜索

### 1.3 集成范围
1. **嵌入生成服务**：调用OpenAI/Azure OpenAI嵌入API
2. **LLM服务**：集成GPT-4/GPT-3.5等大型语言模型
3. **语义内核服务**：封装Semantic Kernel核心功能
4. **提示模板管理**：可配置的提示工程系统
5. **上下文构建服务**：RAG上下文组装和优化

## 2. RAG核心功能需求分析

### 2.1 文本嵌入生成
- **输入**：纯文本字符串
- **输出**：1536维向量（Pgvector.Vector）
- **要求**：
  - 支持批量处理
  - 错误处理和重试机制
  - 速率限制管理
  - 缓存已生成的嵌入

### 2.2 向量检索
- **输入**：查询向量，知识库ID（可选），topK参数
- **输出**：相似度排序的知识块列表
- **要求**：
  - 支持跨知识库检索
  - 可配置的相似度阈值
  - 分页和性能优化
  - IVFFlat索引支持

### 2.3 LLM集成
- **输入**：提示文本，上下文，对话历史
- **输出**：生成的回答
- **要求**：
  - 支持流式输出
  - 可配置的温度、最大token数等参数
  - 系统提示和角色定义
  - 错误处理和回退机制

### 2.4 提示工程
- **输入**：用户查询，检索到的上下文，对话历史
- **输出**：优化的提示文本
- **要求**：
  - 可配置的提示模板
  - 上下文长度优化
  - 支持多轮对话
  - 引用标注和来源追踪

### 2.5 RAG流程协调
- **输入**：用户查询，会话ID，知识库ID
- **输出**：RAG响应（回答+引用）
- **要求**：
  - 端到端的RAG流程
  - 检索日志记录
  - 性能监控
  - 可配置的检索策略

## 3. 服务接口设计

### 3.1 现有接口分析
已定义的领域服务接口：
1. **IVectorRetrievalService** - 向量检索服务
   ```csharp
   Task<IEnumerable<RetrievalResult>> SearchSimilarChunksAsync(string query, int topK = 5);
   Task<Vector> GenerateEmbeddingAsync(string text);
   Task<double> CalculateSimilarityAsync(Vector v1, Vector v2);
   ```

2. **IRagGenerationService** - RAG生成服务
   ```csharp
   Task<RagResponse> GenerateResponseAsync(string query, Guid? sessionId = null);
   Task<RagResponse> GenerateResponseWithContextAsync(string query, IEnumerable<KnowledgeChunk> context);
   Task LogRetrievalAsync(Guid generationId, IEnumerable<RetrievalLog> logs);
   ```

### 3.2 需要新增的服务接口

#### 3.2.1 ISemanticKernelService
```csharp
public interface ISemanticKernelService
{
    Task<IKernel> CreateKernelAsync();
    Task<ISKFunction> CreateFunctionAsync(string promptTemplate, string functionName);
    Task<string> InvokeFunctionAsync(ISKFunction function, ContextVariables variables);
    Task<MemoryQueryResult> SearchMemoryAsync(string query, int limit = 5);

```

#### 3.2.2 IEmbeddingService（可选，可合并到IVectorRetrievalService）
```csharp
public interface IEmbeddingService
{

```

#### 3.2.3 ILLMService
```csharp
public interface ILLMService
```

#### 3.2.4 IPromptTemplateService
```csharp
public interface IPromptTemplateService
{
```

## 5. 配置要求

### 5.1 开发环境
- .NET 10.0
- Microsoft.SemanticKernel 1.73.0+
- OpenAI/Azure OpenAI API密钥
- PostgreSQL with pgvector

### 5.2 配置文件结构
```json
{
  "SemanticKernel": {
    "OpenAI": {
      "ApiKey": "",
      "EmbeddingModel": "text-embedding-3-small",
      "ChatModel": "gpt-4"
    },
    "AzureOpenAI": {
      "Endpoint": "",
      "ApiKey": "",
      "DeploymentNames": {
        "Embedding": "text-embedding-3-small",
        "Chat": "gpt-4"
      }
    }
  },
  "EmbeddingCache": {
    "Enabled": true,
    "Duration": "24:00:00"
  }
}
```

### 5.3 依赖注入配置
```csharp
// Program.cs
services.AddScoped<ISemanticKernelService, SemanticKernelService>();
services.AddScoped<IEmbeddingService, OpenAiEmbeddingService>();
services.AddScoped<ILLMService, OpenAiLLMService>();
services.AddScoped<IPromptTemplateService, PromptTemplateService>();

// 配置选项
services.Configure<OpenAIOptions>(configuration.GetSection("SemanticKernel:OpenAI"));
services.Configure<EmbeddingCacheOptions>(configuration.GetSection("EmbeddingCache"));
```

## 7. 风险与缓解措施

### 7.1 技术风险
1. **API限制和成本**
   - 风险：OpenAI API调用次数限制和成本控制
   - 缓解：实现缓存、批量处理、使用本地模型备选

2. **性能瓶颈**
   - 风险：向量检索和LLM调用可能成为瓶颈
   - 缓解：优化索引、添加缓存、异步处理

3. **模型版本兼容性**
   - 风险：API模型版本更新导致兼容性问题
   - 缓解：抽象模型配置、版本隔离、测试覆盖

### 7.2 项目风险
1. **集成复杂性**
   - 风险：Semantic Kernel学习曲线和集成复杂性
   - 缓解：分阶段实施、充分测试、文档完善

2. **依赖管理**
   - 风险：NuGet包版本冲突和依赖管理
   - 缓解：锁定版本、定期更新、兼容性测试
